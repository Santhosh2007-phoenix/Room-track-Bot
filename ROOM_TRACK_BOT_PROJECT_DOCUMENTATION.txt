1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
ROOM TRACK BOT is an AI-powered, touchless, multilingual indoor hospital navigation
and patient tracking bot. It combines edge IoT hardware (ESP32), digital acoustic
sensing (INMP441 I2S), Cloud Speech-to-Text AI (Groq Whisper), and cloud hospital
records (Supabase PostgreSQL) to enable visitors to locate admitted patients simply
by speaking naturally, with zero typing or English literacy required.


2. TARGET USERS
--------------------------------------------------------------------------------
A. PRIMARY USERS: Hospital Visitors & Attenders
   - Relatives, rural visitors, elderly individuals, and distressed family members.
   - Pain points solved: Inability to read complex hospital signs, anxiety in large
     multi-floor corridors, inability to type on touchscreen kiosks.

B. SECONDARY USERS: Front-Desk, Helpdesk & Nursing Staff
   - Receptionists, nurses, and hospital security personnel.
   - Pain points solved: 40-60% of front-desk inquiries are repetitive questions
     ("Where is Room 204?", "Where is Vel admitted?"). Frees hospital staff to focus
     on emergency admissions and core clinical duties.

C. TERTIARY USERS: Hospital Management & Administration
   - Facility Directors in Government and Private Multi-specialty Hospitals.
   - Pain points solved: Prevents reception corridor crowding, cuts kiosk capital
     expenditure by 95%, and improves patient/visitor satisfaction (NABH/JCI metrics).

4. COMPETITOR ANALYSIS & EXISTING ALTERNATIVES
--------------------------------------------------------------------------------
1. Manual Help Desks / Reception Staff:
   - Limitations: Recurring monthly salary expenses, long queues during visiting hours,
     staff fatigue, and unavailable 24/7.

2. Commercial Touchscreen Kiosks (e.g., Purple Wayfinding, LogicJunction):
   - Limitations: Touchscreens harbor germs and viruses (high nosocomial cross-infection
     risk in hospitals). Requires English typing literacy; rural and elderly visitors
     struggle with on-screen keyboards. High cost (Rs. 1,50,000 to Rs. 4,00,000 per kiosk).

3. Indoor Beacon / Smartphone Apps (e.g., Pointr, Steerpath):
   - Limitations: Requires visitors to download an app and turn on Bluetooth. Over 90%
     of visitors refuse to download an app just for a 20-minute visit.

4. Static Directional Boards & Printed Floor Maps:
   - Limitations: Confusing, cannot update dynamically when patients are moved or discharged.

7. COMPLETE TECH STACK
--------------------------------------------------------------------------------
- Edge Controller:      ESP32-D0WD-V3 (Dual Core 240MHz, Wi-Fi 802.11 b/g/n)
- Firmware Environment: C++ / Arduino IDE 2.x, driver/i2s.h, ArduinoJson v7
- Acoustic Sensor:      INMP441 MEMS Omnidirectional Digital I2S Microphone
- Proximity Sensor:     HC-SR04 Ultrasonic Transducer (2cm - 400cm range)
- Audio Synthesizer:    DFPlayer Mini Hardware MP3 Decoder + 24-bit DAC
- Display Interface:    LCD 1602 with PCF8574 I2C Backpack
- Backend Server:       Node.js (v20+), Express.js REST API
- Auto-Discovery:       UDP Broadcast Beacon (Port 4001/4002 via Node dgram)
- Cloud Speech-to-Text: Groq Cloud Whisper API (model: whisper-large-v3)
- Primary Database:     Supabase Cloud Managed PostgreSQL (PgPool)
- Local Fallback DB:    SQLite3 (better-sqlite3)
- Frontend Web:         React 18, TypeScript, Vite 5, Tailwind CSS
- Wayfinding Engine:    Interactive 2D SVG Blueprint with animated walking trail
- Messaging Gateways:   Fast2SMS Quick Route & CallMeBot WhatsApp Gateway

9. END-TO-END DATA FLOW
--------------------------------------------------------------------------------
1. Detection: Visitor approaches within 40 cm. HC-SR04 ultrasonic confirms visitor
   presence for 500 ms.
2. Welcome: LCD displays "Welcome to Room Track Bot". DFPlayer Mini plays Track 1
   (Welcome voice message).
3. Prompt: LCD prompts "Press Button To Speak Name...".
4. User Action: Visitor presses Push Button (GPIO 23).
5. Audio Capture:
   - Green LED turns ON instantly.
   - I2S DMA buffer is flushed.
   - INMP441 records 3 seconds of 16-bit PCM audio (48,000 samples @ 16 kHz).
   - Stereo channel auto-picker selects live mic signal per sample.
   - Green LED turns OFF; LCD displays "Searching... Processing Voice".
6. Audio Transmission:
   - ESP32 builds standard 44-byte RIFF WAV header + 96,000 bytes PCM payload.
   - Streams multipart HTTP POST request to /api/device/voice-search.
7. Backend AI Processing:
   - Buffer amplitude validation: Checks PCM peak level (must be >= 150).
   - Dynamic prompt generation: Queries active admitted patients and generates
     custom STT biasing prompt ("Hospital admitted patients: Vel, Santhosh...").
   - Dispatches audio to Groq Whisper Cloud (whisper-large-v3).
   - Cleans response and filters silence hallucinations.
8. Database Search:
   - Multi-token fuzzy search in Supabase PostgreSQL against patient name,
     father's name, and city.
9. Announcements & Attender Alert:
   - IF FOUND:
     * LCD displays: "VEL / 2F Room:203"
     * Speaker announces: English ("Second Floor, Room 203") + Tamil ("இரண்டாம் தளம், அறை எண் 203").
     * Backend triggers Fast2SMS and WhatsApp alert to the patient's relative.
     * LCD displays "Thank You / Take Care", waits 6 seconds, and resets to Standby.
   - IF NOT FOUND:
     * LCD displays: "Patient Not Found".
     * Speaker plays Track 7 (Not Found prompt).
     * System immediately loops back to "Press Button To Try Again...".


10. INTER-COMPONENT COMMUNICATION PROTOCOLS
--------------------------------------------------------------------------------
A. INMP441 to ESP32:
   - Digital I2S protocol using DMA channels.
   - 32-bit slot stereo stream @ 16,000 Hz, scaled to 16-bit PCM with >> 12 gain.

B. DFPlayer Mini to ESP32:
   - UART serial communication via HardwareSerial 2 at 9600 baud, 8N1.
   - Frame command: 0x7E 0xFF 0x06 0x12 0x00 [TrackHigh] [TrackLow] 0xEF.

C. LCD Display to ESP32:
   - I2C bus protocol at address 0x27 (standard 100 kHz speed).

D. ESP32 to Backend Server:
   - Zero-configuration UDP Broadcast Beacon:
     * ESP32 sends "DISCOVER_ROOM_TRACK_BOT" on UDP port 4001.
     * Server replies "RTB_SERVER_ACK" on UDP port 4002.
     * ESP32 auto-configures the server's IP address dynamically.
   - HTTP Multipart POST:
     * Endpoint: POST /api/device/voice-search
     * Authentication: X-API-Key header
     * Content-Type: multipart/form-data; boundary=----ESP32Boundary...
   - HTTP Status Polling:
     * POST /api/device/heartbeat every 5 seconds.
     * GET /api/device/next-patient every 2 seconds for website dispatches.

E. Backend to Groq Whisper Cloud:
   - HTTPS REST API call to https://api.groq.com/openai/v1/audio/transcriptions.
   - Model: whisper-large-v3 with Bearer token authentication.

F. Backend to Supabase PostgreSQL:
   - Encrypted PostgreSQL Wire Protocol (TCP over SSL) via Node 'pg' Pool.
   - Parameterized queries with sub-10ms response time.

G. Backend to Attender Gateways:
   - HTTPS REST calls to Fast2SMS and CallMeBot WhatsApp API.
